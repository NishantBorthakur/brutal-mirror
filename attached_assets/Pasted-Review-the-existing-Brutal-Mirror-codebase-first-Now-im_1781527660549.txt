2. DATABASE SCHEMA
==================================================

Create a SQL schema file:

supabase/schema.sql

Add these tables:

A. profiles

Fields:
- id uuid primary key references auth.users(id) on delete cascade
- email text
- display_name text
- credits_balance integer not null default 0
- free_credits_granted boolean not null default false
- created_at timestamptz default now()
- updated_at timestamptz default now()

B. credit_transactions

Fields:
- id uuid primary key default gen_random_uuid()
- user_id uuid references profiles(id) on delete cascade
- type text not null
- credits integer not null
- balance_after integer
- reason text
- metadata jsonb default '{}'::jsonb
- created_at timestamptz default now()

Allowed transaction types:
- free_grant
- usage
- purchase
- refund
- adjustment

C. roast_logs

Fields:
- id uuid primary key default gen_random_uuid()
- user_id uuid references profiles(id) on delete set null
- category text
- intensity text
- personality text
- refinement_mode text
- input_preview text
- input_tokens integer default 0
- output_tokens integer default 0
- total_tokens integer default 0
- credits_used integer default 1
- success boolean not null default true
- error_message text
- created_at timestamptz default now()

Enable Row Level Security on all tables.

RLS policies:
profiles:
- Users can select their own profile.
- Users can update only their own display_name.
- Users must not directly update credits_balance or free_credits_granted from frontend.

credit_transactions:
- Users can select their own transactions.
- Users cannot insert/update/delete transactions from frontend.

roast_logs:
- Users can select their own roast logs.
- Users cannot insert/update/delete roast logs from frontend.

Backend with service role should handle credit updates and logs.

Add a trigger:
- When a new auth.users record is created, automatically create a profile row.

6. CREDIT DEDUCTION RULES
==================================================

A roast or refinement costs 1 credit.

Rules:
- Fresh roast = 1 credit
- Make it sharper = 1 credit
- Make it funnier = 1 credit
- Make it more professional = 1 credit

Credit should be deducted only after successful AI response.

Do not deduct credits if:
- validation fails
- user is not logged in
- user has no credits
- API call fails
- AI returns invalid JSON
- backend throws error

If user has 0 credits:
- Block generation before calling AI.
- Show upgrade placeholder:
  “You’re out of credits.”
  “Credit purchases are coming soon.”
- Do not call backend AI endpoint.

7. BACKEND CREDIT CHECKING
==================================================

Update POST /api/roast.

The request should include the user auth token from Supabase.

Backend flow:
1. Verify Supabase user from Authorization header.
2. If no valid user, return 401.
3. Fetch user profile using service role.
4. If credits_balance <= 0, return 402-style error:
   {
     "error": "OUT_OF_CREDITS",
     "message": "You are out of credits."
   }
5. Run AI roast generation.
6. If AI succeeds and valid JSON is returned:
   - Deduct 1 credit from profiles.credits_balance.
   - Insert credit_transactions row:
     type: usage
     credits: -1
     reason: "Roast generation" or "Roast refinement"
     balance_after: new balance
     metadata containing category, intensity, personality, refinementMode
   - Insert roast_logs row:
     user_id
     category
     intensity
     personality
     refinement_mode
     input_preview
     input_tokens
     output_tokens
     total_tokens
     credits_used: 1
     success: true
7. Return AI result plus updated credits balance.

If AI fails:
- Insert roast_logs row with success=false if possible.
- Do not deduct credit.
- Return clean error.

Important:
Credit deduction must be server-side.
Frontend must never directly modify credits_balance.
